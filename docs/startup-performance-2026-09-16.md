# Mobile startup optimization — 2026-09-16

## Scope

Follow-up to the supplied Lighthouse 13.4.1 report for the deployed Pocket homepage. Preserve the current theme layouts, saved preferences, language-neutral first paint, game gesture surfaces, and complete PWA route coverage.

## Changes

- Pre-hydration bootstrap loads only the selected theme's base stylesheet. Styles use content-hashed URLs generated by `scripts/build-theme-assets.mjs`; the original theme sources remain in `styles/themes/`. Existing classic/focus route-only CSS stays route-loaded.
- Theme switches wait for the new stylesheet, preserve the current page's state, and keep the previous theme/preference if loading fails. Failed requests can be retried. Initial load failures expose a retry action instead of an indefinite placeholder.
- Keep iOS safe-area overrides after theme rules in generated bundles, preserving their original cascade order. Standard `pnpm dev` watches theme and safe-area sources.
- Preload the Pocket document illustration before hydration using the exact rendered responsive source set; don't preload Pocket artwork for another saved theme or secondary route. Keep its image eager/high-priority and other images selectively eager/lazy.
- Build local 96/160/240px WebP variants plus a 256px document variant for 2x mobile displays. Retain original 320px files. No runtime image optimization service is required, and all variants enter the full offline manifest.
- Replace eager viewport-wide link prefetch with pointer/touch/focus intent. Explicit `prefetch={true}` still opts into viewport prefetch; offline and explicit `false` still disable it.
- Defer normal web service-worker **registration itself** until 30 seconds after load, then idle. Explicit installation preparation uses a shared, retryable registration immediately. Installed PWA startup retains immediate idle preparation. The worker still installs all 24 routes before activation; do not replace this with a home-only install that can regress offline coverage during upgrades.
- Include selected-theme styles in core offline preparation, bump worker cache version to v26, stop preloading the unused-on-home monospace font, restore browser zoom, and darken Pocket text-card secondary copy.

Generated styles, image variants, resource manifests, screenshots and browser reports remain ignored build/QA artifacts. `pnpm build`, `pnpm test`, `pnpm typecheck`, and the development/build phases of the Next config prepare required theme assets; production offline manifest generation follows the asset build. `next start` does not regenerate files or require build-only image/CSS dependencies.

## Verification and limits

- Regression tests cover zoom, theme loading boundaries, intent prefetch, registration scheduling, bootstrap request deduplication/retry/timeouts, LCP responsive source consistency, generated image dimensions and offline inclusion.
- Production Chromium mobile-context checks verify first visit chooses Pocket/Chinese, only one theme stylesheet loads, and there are no speculative RSC requests or service-worker registrations during the initial observation window.
- Five-theme switching on the text tool preserves input; a simulated failed theme stylesheet request retains the working theme and does not persist the failed choice.
- Full offline preparation reports 24 routes. Explicit offline navigations exercised `/`, `/text-tool`, `/base64-tool`, `/2048`, `/schulte-grid`, and `/anime-tracker`, plus theme switching and a cold document reload offline.
- Local Lighthouse runs pass image delivery, LCP discovery, contrast and viewport checks; accessibility, best practices and SEO score 100. Initial local runs recorded 26 requests / approximately 398 KiB versus the supplied deployment report's 83 / 757 KiB. These are different environments, not a controlled production before/after benchmark.
- Performance in those local runs remained 91–92 and simulated LCP 3.3–3.5 seconds. Fixing image discovery does not eliminate the remaining client-render/hydration dependency. Framework JavaScript coverage and required shared render-blocking CSS must not be blindly deleted to silence diagnostics. No claim of a production LCP pass or a perfect performance score is made.
- iOS/Android installed-app device validation and post-deployment Lighthouse sampling remain separate checks; desktop mobile emulation is not physical-device proof.
